# 那袋盐怎么配

腌菜、卤味、泡萝卜这类活儿，配方几乎都写成「盐占水的百分之几」，可手边只有一个固定容积的罐子。
这个单文件网页把「罐子多大、放多少菜、想出多少咸」换成一张能直接照着下的配盐单：
**下多少克盐、兑多少毫升水、菜自己会出的水要补多少**。

## 它算的是什么

- 目标盐度（质量分数）↔ 每升含盐量 ↔ 盐水密度（0–26 % 线性内插，`ρ = 0.9982 + 0.00740 w`）
- 罐子容积 → 菜以外空间 → 液体可用体积（扣掉菜渗出的水与预留液面空间）
- 已有的盐水（上次剩的、或已经泡着的）按它自己的浓度折算进来，只算一次
- 菜渗水会把盐度拉低多少；要「一次到位」该多下多少盐（`Δ = w/(100−w) × 菜渗水`）
- 盐的堆积体积与平勺对照、整袋盐采购取整与成本、每 100 mL 液体的定额（换罐子直接乘）
- 4 / 6 / 15 % 三档对照、0.5–10 L 逐档重算、8 项结构自检（每次重算都跑）

## 它不做什么（重要）

- **不做食品安全判定**：不判断任何浓度能不能吃、能不能放、能放多久；不给杀菌、亚硝酸盐相关结论或建议。
- **不内置任何菜品配方**：页面上的 4 / 6 / 15 % 只是对照档位，不是推荐值；目标盐度由你填。
- **不建模**：盐的溶解速率与饱和、菜吸盐、发酵产气产酸、蒸发与温度、微生物过程、渗出过程的时变。
- **不联网**：不查真实盐价、不查配方、不引用任何机构建议；不内置标准号。
- 近似口径：盐溶入水按体积加和（实际浓度会略高于页面读数）；「蔬菜占容积」「出水率」「食盐堆积密度」
  都是你填的假设，页面不校验它们是否自相矛盾。
- 默认场景与 10 个内置场景**全部是虚构示例**。

## 怎么用

打开 `index.html` 即可，无依赖、不联网。改任意输入立即重算；可保存到本机并在刷新后恢复；
可导出 CSV / 文字说明 / 1080×1350 结果卡 / JSON 备份。

## 工程结构

```
index.html      由 template.html + core.js + ui.js 拼出的单文件（部署用）
core.js         纯计算内核（不碰 DOM，可被 node --test 直接测）
ui.js           界面层：只画内核的结果，不自己算数
template.html   骨架与样式（/*CORE*/ 与 /*UI*/ 两个占位符）
build.cjs       node build.cjs → index.html
tests/core.test.cjs   node --test tests/core.test.cjs
make-cover.cjs  生成封面 SVG（数字全部来自 core.js 对默认场景的真实计算）
验收.cjs / 截图.cjs / 裁图.cjs  浏览器验收与目检取证脚本
```

## 测试

```
node --test tests/core.test.cjs
```

本轮 77 项全过（fail / cancelled / skipped / todo 全 0）。测试纪律：手算锚点写在测试里、不从实现输出里抄；
`ok=false` 时断言「算不出来」而不是断言 0；随机 300 组 × 15 条不变量；
**页面给出的每一条带数字的建议，都会被「按它重算一遍」验证**（留量重算后盐度必须回到目标、换罐子重算后必须算得出来）。
